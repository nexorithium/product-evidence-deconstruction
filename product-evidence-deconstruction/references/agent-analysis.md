# Agent 分析规范

仅在拆解 Agent 清单、Agent 契约或单 Agent 功能等价提示词时读取本文件。

## 识别实际出现的 Agent

只有存在可见名称、独立职责、代码定义、任务/运行对象或明确输出时，才能记录为实际 Agent。计划文字中提到的角色，只有在独立加入、回复、接收任务或产出结果后，才能计入 Agent 清单。

对每个 Agent 识别首次和后续出现时间、触发者、上游、下游、用户修改后是否重新进入、职责范围与边界、确认门、自动继续条件、停止条件，以及完成或交接证据。

## 六类输入契约

分别检查：

1. **用户当前输入**：需求、选择、反馈、修改、确认、中断、上传材料。
2. **用户长期信息**：语言、套餐、额度、已保存资产、身份参考、音色、偏好、权限、历史。只有页面可见时才能标为已确认。
3. **项目全局上下文**：配置、内容、风格、领域对象、引用、当前状态、确认、模型设置、历史、失败、生成资产。
4. **上游 Agent 输出**：生产者、传递的字段/资产、当前 Agent 如何使用、启动前提和上游修改后的重跑要求。
5. **平台知识与资产**：风格库、模型库、专业知识、模板、安全、版权、计费和能力限制。
6. **工具与运行时结果**：成功、部分成功、失败、安全拦截、额度错误、中断、重试、状态写入、资产引用和历史版本。

## 可观察判断契约

不得还原私有思维过程。只总结行为暴露出的功能判断：要解决的问题、输入是否齐全、下一步选择、等待确认还是自动继续、停止条件、修改处理、工具失败处理、完成判断，以及是否实际验证质量和状态。

每条判断标记为【已确认】、【合理推断】、【建议设计】或【未知】。

## 工具契约

对每个有证据支持的工具或工具型功能，记录：

- 功能名称及是否为官方名称；
- 调用者；
- 输入和前置条件；
- 是否需要用户确认；
- 可见成功结果与后置条件；
- 失败结果；
- 重试证据；
- 幂等与重复扣费风险；
- 中断处理；
- 资产成功但状态写入失败时如何处理。

不得编造看起来像官方接口的名称。

## Agent I/O 契约卡

固定结构：

1. Agent 名称
2. 核心目标
3. 触发条件
4. 按六类来源整理的输入契约
5. 可观察判断
6. 工具契约
7. 输出契约：用户回复、页面组件、结构化字段、资产、状态、下游任务
8. 全局上下文读写表
9. 完成条件
10. 异常、重试与未知问题

全局上下文读写表必须包含：字段/对象、读取/写入、生产者、消费者、更新时间、证据等级、证据编号。

## 单 Agent 功能等价提示词模式

先收集目标 Agent 在当前任务中的全部可观察记录。若目标名称仍是占位符或存在歧义，应停止并请用户明确；不同选择会实质改变结果时，不得替用户选择 Agent。

交付顺序：

1. 目标 Agent 的证据范围与边界；
2. 输入契约；
3. 输出契约；
4. 工具契约；
5. 状态机与 Mermaid 状态图；
6. 已确认规则、推断规则、建议规则和未知事项；
7. 可直接使用的功能等价 System Prompt；
8. 规则—证据追溯表；
9. 最小测试集；
10. 仍然无法确认的问题。

### 状态机

状态必须从证据中推导。可以检查但不得强行使用：

- `waiting_input`：等待输入；
- `planning`：规划；
- `waiting_confirm`：等待确认；
- `executing`：执行工具；
- `validating`：验证结果；
- `completed`：完成；
- `failed`：失败；
- `interrupted`：用户中断；
- `retrying`：准备重试；
- `handoff`：下游交接。

明确每个状态允许的事件、动作、写入和禁止行为。没有页面支持的失败/重试转换只能标记为【建议设计】或【未知】。

### 功能等价 System Prompt 结构

1. Agent 名称
2. 角色
3. 核心目标
4. 任务边界
5. 输入契约：必填与可选
6. 全局上下文协议：允许读取、允许写入、禁止修改、生产者、消费者、失效关系
7. 编号工作流程：进入条件、判断、工具、状态写入、确认门和下一状态
8. 工具规范：使用 `<生成图片>` 等占位名称
9. 用户确认机制
10. 结果验证
11. 修改、版本、失效和回退
12. 异常处理
13. 状态机
14. 下游交接载荷
15. 完成条件
16. 结构化输出格式

Prompt 外部的每条行为规则必须保留证据等级。Prompt 内部若混合了兼容现有行为的规则和增强稳定性的建议，应明确区分。

### 最小测试集

至少覆盖：正常输入完整、缺少必需输入、局部修改、工具失败、用户中断、全局上下文与页面状态冲突。

每个测试包含：测试输入、初始状态、预期判断、预期工具调用、预期状态变化、不允许出现的行为。
