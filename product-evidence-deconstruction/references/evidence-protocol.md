# 证据协议

解释产品行为前，先执行本协议。

## 证据来源清单

为每条证据分配稳定编号，并标记来源类型：

- 用户动作或用户输入；
- 聊天记录或 Agent 回复；
- 按钮、表单、选项、确认或导航状态；
- 画布、工作区、文档或资产卡片；
- 任务、工作流、进度、历史或版本状态；
- 模型选项、能力、价格、额度或分辨率；
- 工具结果或运行时结果；
- 错误、警告、中断、安全或计费信息；
- 用户提供的源代码、数据结构、日志或测试；
- 第一方官方资料。

截图证据需记录截图编号和可见区域；现场产品需保留时间顺序、页面标题或网址，但不得暴露敏感会话数据；源代码尽量标注文件和行号。

## 不同拆解深度的最低证据

### 用户旅程

至少需要初始输入、主要用户选择、产品反馈、结果状态或资产，以及当前终点。只有互不连贯的最终状态截图，不足以还原完整旅程。

### Agent 契约

至少需要可观察的 Agent 身份或独立职责、触发条件、一项输入、一项公开判断/计划摘要、一项输出或结果，以及完成或交接证据。不得因为某类产品通常存在某个 Agent 就把它加入清单。

### 功能等价 Agent 提示词

至少需要目标 Agent 在当前任务中的完整可观察记录、输入/输出契约、工具或工具结果、确认门、停止行为、状态变化和下游边界。证据不完整时，只输出范围明确的部分提示词，或请求补充材料。

### 完整产品架构

至少需要用户流程证据，以及足以追踪一个完整任务的 Agent、工具、状态和资产证据。源代码或官方资料可以增强基础设施结论，但能力级架构不强制要求它们。没有直接证据时，不得声称产品使用某个数据库、消息队列、云服务、语言或厂商。

## 结论分类

- **【已确认】**：引用来源直接支持。
- **【合理推断】**：多条已确认观察共同指向，但实现不可见。
- **【建议设计】**：为解决风险或缺口提出的改进方案。
- **【未知】**：证据不足。

界面存在某个字段，只能证明该字段可见，不能自动证明 Agent 读取了它；Agent 展示某个计划，只能证明计划被展示，不能证明工具已经执行。确认工具执行需要工具结果、资产变化或状态变化。

## 时间顺序证据表

| 证据编号 | 时间/顺序 | 用户目标/动作 | 产品/Agent | 可见判断摘要 | 控件/工具结果 | 状态/资产变化 | 用户确认 | 失败/纠偏 | 来源 |
|---|---|---|---|---|---|---|---|---|---|

不得为了让流程看起来连贯而补写不存在的中间步骤。

## 冲突检查

至少对比：

- 自然语言中的“完成”声明；
- 任务或工作流状态；
- 工作区或画布资产；
- 资产库和历史版本；
- 预览、播放或导出可用性；
- 错误或素材不完整提示；
- 与任务相关的余额或额度状态。

冲突时同时记录双方。只有必需资产存在、状态写入成功、结果校验通过且必要用户确认已记录时，才能认定真正完成。

## 现场检查边界

默认只读。可以打开已有记录、滚动、展开公开计划摘要、切换只读分类、打开已有预览。除非用户明确授权，不得触发生成、对外沟通、购买、删除、发布或权限变更。

需要登录、双重验证、验证码或用户接管时暂停，并请用户完成。不得检查浏览器存储或凭证。
