# 产品类型路由

选择拆解重点前，先判断产品类型。一个产品可以有一个主要类型和多个次要类型。

## 生成式创作工具

重点检查提示词、配置和参考资料输入；分阶段生成；用户确认门；模型选项与限制；资产血缘和版本；风格/角色一致性；预览、编辑与导出；部分成功、重试、成本；以及页面中的“已生成”到底代表中间资产还是最终交付物。

## 通用执行 Agent

重点检查目标理解、任务规划、工具授权、外部副作用、观察—判断—行动—验证闭环、状态机、异步执行、中断、重试、幂等、审计、交接、恢复和完成标准。

## 对话或陪伴产品

重点检查人设与语气一致性、关系模型、短期/长期记忆、个性化与同意机制、情绪推断的不确定性、主动/被动交互、安全升级、依赖风险、隐私，以及记忆纠正与删除。

## Copilot 或编辑器

重点检查真实文档/项目事实源、建议与直接修改的边界、选区范围、差异预览、应用/拒绝/撤销、版本历史、自动保存、协作、权限、冲突和宿主应用内验证。

## 企业工作流产品

重点检查角色、权限、租户、审批门、连接器、数据契约、同步、确定性策略、服务等级、任务队列、负责人、升级、审计和人工复核。

## 分类输出

报告中写明：

1. 主要产品类型；
2. 次要产品类型（如有）；
3. 支持分类的证据；
4. 因分类而提高权重的拆解内容；
5. 被主动弱化的通用模板内容。

不要因为产品有聊天界面就把它认定为 Agent 产品。还需寻找可观察的规划、工具使用、持续任务状态或实际行动。
